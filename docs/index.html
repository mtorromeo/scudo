scudo

Sandbox any command,
without thinking about it.

scudo wraps commands with systemd-run, applying resource limits, filesystem, session bus and network restrictions from per-command profiles. Symlink it under a command's name, or let the FUSE shim do it for every command on your PATH.

Read the documentation View on GitHub 
# ~/.config/scudo/config.toml
[sandboxed]
filesystem.read = ["/"]
filesystem.write = ["/tmp", "$XDG_RUNTIME_DIR"]
filesystem.hide = ["$HOME"]

[cargo]
match = "cargo"
extend = "sandboxed"
filesystem.write = ["$HOME/.cargo", "$PWD"]
systemd.MemoryMax = "4G"
network.dest.allow = ["*.crates.io"]
network.ports.allow = [443]

What it does

Profiles per command

Match commands by exact name, glob or regex, layer profiles with extend, and override them per directory with a .scudo.toml you are asked to trust first.

Filesystem & resources

Read-only, writable and hidden paths, memory and CPU limits, capability drops: anything a systemd unit can say, with no root and no container image.

Network filtering

Allow and deny destinations, hosts and ports with eBPF programs attached to the command's cgroup. Naming a host is what lets it resolve.

See what was blocked

Refused connections, DNS lookups and hidden files are reported as they happen, or side by side with the command in the --tui terminal UI.

How you run it

Explicitly

$ scudo curl https://example.com
$ scudo --tui -- curl https://example.com/
$ scudo --allow-dest api.github.com cargo build

Transparently

$ ln -s /usr/bin/scudo ~/.local/bin/curl
$ curl https://example.com  # sandboxed

# or for every command on PATH
$ systemctl --user enable --now scudo-fuse
