## Project

`scudo` wraps commands in `systemd-run --user --wait -qPdt`, applying the constraints of the profiles that match the command name and `$PWD`. Invoked through a symlink (busybox-style), argv[0] selects the profile and the call is rewritten to `scudo -- <command> …`, so every flag after it belongs to the command.

## Commands

```bash
cargo test <name>       # single test (substring)
cargo clippy --all-targets && cargo clippy --no-default-features --features bpf
cargo +nightly fuzz run dns fuzz/corpus/dns fuzz/seeds/dns
git cliff --unreleased  # what the next release would add
cargo make release [VERSION]
```

- `CHANGELOG.md` is generated by git-cliff from commit subjects and written only by `cargo make release`: write commits as `type(scope): summary` (`!` + `BREAKING CHANGE:` footer when breaking) and leave the file to the tool.
- `fuzz/` is its own workspace, built without `bpf`. Targets assert properties, so modules they reach (`bpfd::dns`, `tui::query`) stay public and outside `bpf`. Seeds are tracked in `fuzz/seeds/`.

## Rust conventions

- Diagnostics go through `tracing`. `eprintln!` is for interactive output only (trust diff, `[y/N]` prompt, echoed command) and for `scudo-bpfd` / `scudo-fuse`.
- Clippy runs `pedantic` + `restriction` with `-Dwarnings`. Frequent hits: `arithmetic_side_effects` (use `saturating_*`), `let_underscore_must_use` (use `drop(...)`). When the lint is wrong for the code, use a narrow `#[expect(…, reason = "…")]`.
- Prefer libc over a new crate when the C call is a few lines.
- `exec` into `systemd-run` rather than spawning, so signals propagate.
- A worker thread sleeping in `poll` also waits on `Shutdown::wake_fd()` (`src/bpfd/worker.rs`): workers are joined under the daemon's state lock, on every command's registration path.

## Config and profiles

- Search order, first match wins: `$PWD/.scudo.toml`, `$XDG_CONFIG_HOME/scudo/config.toml`, `/etc/scudo/config.toml`.
- Each TOML section is a profile; `[scudo]` is reserved for scudo's own settings (`[scudo.log]`, `[scudo.tui]`) and a profile key there is an error. Section names serve only `extend` and `--profile`; only `match` (`{ pattern, type = "exact"|"glob"|"regex" }`) matches commands. A profile without `match` is a base for `extend`.
- Precedence: glob < regex < exact < `--profile`.
- Resolution flattens the whole `extend` graph into one merge order (each profile after its bases, shared bases applied once) and merges each profile once. Merging branches separately would resolve `"..."` early and make one branch's list replace its sibling's.
- Unit properties live only in the `systemd` sub-table, so every other key is known and an unknown one is rejected as a typo. `network` is kept as raw TOML (for `"..."` splicing); `log` is parsed at load time and merged field by field with `.or()`.
- Single-valued properties a profile sets are never overwritten by what scudo adds (only warned about); lists are appended to.

## Network (`scudo-bpfd`)

- `dest` and `ports` each have `allow`/`deny`. They are sources of permission: any deny wins, any allow suffices, else the default. `ports.allow` widens to every address. List order is unobservable, so merging is a union.
- Deny-all is `PrivateNetwork=yes`; everything finer is eBPF attached by `scudo-bpfd` (systemd's `IPAddressAllow=`/`SocketBind*=` are ignored in user units). The daemon only ever adds restrictions to a cgroup the caller owns. Its wire protocol is a list of tagged policies, so new kinds need no protocol change.
- **The eBPF programs are loop-free, including the emit path** (reserve, write, submit, per-CPU drop counter). Destinations are LPM tries (deny/allow × v4/v6), ports are bitmaps, so policy size has no cap.
- Denial reporting is switched by rewriting the `LOG_DENIALS` `.rodata` global (same trick as `PORTS_DENY_SET`), so when off the verifier drops the emit sites.
- Naming a host is what allows resolving it. DNS is redirected to a per-sandbox resolver that inserts answers as full-length prefixes. Expiry removes them; the programs carry no expiry check (a stale `/32` would shadow shorter prefixes). Removal skips prefixes the config declared outright.
- `scudo` and the shim both exec away, so `scudo --bpf-watch <token>` reports denials. The event bus exists from registration, before attachment.

## Filesystem reporting (`src/bpfd/fsmon.rs`)

- `Policy::Filesystem` enforces nothing; systemd does. It only obtains a registration/token/bus and a shim inside the cgroup.
- `scudo-fs` is loaded once for the whole daemon (first sandbox that asks, dropped with the last), never per sandbox: it is system-wide syscall tracing.
- The `WATCHED` map is a security boundary: filtering by exact cgroup id happens in the kernel, because the daemon holds capabilities the caller lacks.
- Raw tracepoints on `sys_enter`/`sys_exit` only: classic tracepoints need tracefs (root-only). Each program first matches the syscall number from the context, before any map access; keep that order.
- Path captured on enter, error on exit, joined by a `PENDING` LRU keyed by `pid_tgid`; remove the entry on success too. On exit the syscall number comes from `orig_rax`.
- Only x86-64 syscall tables exist, guarded by `compile_error!`; add another architecture with its real table.
- `src/bpfd/outside.rs` tells refusals from paths that never existed. Levels: `warn` refused, `debug` missing, `info` unknown. `Notification::is_denial()` is the single predicate.
- `CAP_PERFMON` is optional: its absence warns and costs only reporting (`caps::check()` requires `CAP_BPF` + `CAP_NET_ADMIN`). A failed load is remembered (`FsMonitor::Failed`), never retried.
- Relative paths resolved via `/proc/<pid>/cwd` can race; accepted.

## Logging (`src/logging.rs`)

- Sources, lowest first: `[scudo.log]`, profiles, CLI/`SCUDO_LOG_*`. `verbose` = `log.level = "debug"`; an explicit level beats it. Dropping `-q` and enabling denial reports follow the effective level.
- The subscriber is installed by `logging::init()` and later swapped by `Handle::reconfigure`. Attach the filter as its own layer, never `Layer::with_filter` (a reloaded layer has no `FilterId` and panics).
- The stderr writer turns `\n` into `\r\n` on a terminal.

## TUI (`--tui`, `src/tui/`)

- scudo stays alive here: own pty, in-process notification subscription, no watcher. `runner::build`/`runner::render` keep one command-line builder for both paths.
- Panel width is state (`state.rs`, `$XDG_CONFIG_HOME/scudo/state.toml`), never config. `App.panel_width: Option<u16>`: `None` means follow the screen; "auto" is stored as absence. State-file errors never stop a command.
- Theme (`theme.rs`) is fixed, never derived from the host's colours; only colour depth is detected. Paint everything except the terminal pane. Avoid `REVERSED` (it propagates into spans). Each status-bar state colours the whole bar.
- Section headings sit in their own row (`ui::section_body`); the scrollbar gutter is always reserved.
- `query.rs` answers terminal queries by shape: capabilities (`DA1`, `DA2`, `DSR`, cursor) as scudo's own, colours from the host (asked once at startup, in raw mode, before the input thread). Answering `DA` unblocks every probe; leave unknown queries unanswered.
- Resizing must reach the inner pty via `SIGWINCH` on `systemd-run`; it has its own test.
- The parent drops every copy of the pty slave (`Pty::spawn`), or output never ends.
- Keys go to the command unless prefixed, re-encoded per the program's modes (application cursor). Mouse is captured only while the program requests it.
- Logging to stderr is set to `off` while the UI runs; `tui::run` returns its summary for the caller to print after restoring logging.
- The daemon's `Notification::Summary` beats the panel's counts; without it, say the totals are partial.
- The path tally is bounded and kept ordered by moving, not sorting; eviction drops misses before refusals (`denials::evict`, `denials::drop_one`).

## Delegation (`src/broker.rs`)

- `delegate` picks target profiles that are `delegable` and have a `match`; the opt-in is on the target. `--delegate`/`--no-delegate` are refused inside a sandbox.
- The broker runs the same binary outside with `--delegated <id>`, so everything goes through `run()`; keep logic out of the broker.
- The request widens nothing: only the command name selects profiles; only peers in the caller's unit are served; cwd and every path in `ResolvedProfile::derived` must be the same inode outside and under a root the caller can write. A delegated run never prompts (untrusted `.scudo.toml` and `confirm` are errors) and always ends sandboxed.
- Fail closed: an unresponsive broker is an error.
- Stop by unit name (`systemctl --user stop`/`kill`); `SIGWINCH` goes to `systemd-run`.
- Command and watcher output go to the requester's stderr (`runner::Options::stderr`); scudo's own logs stay on the broker's.
